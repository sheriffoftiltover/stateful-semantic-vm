# Engineering log (spec §60-style: deterministic-runtime fixes before DEV, logged)
1. **Before DEV (unit suite, test `verifier_rejects_bad_candidates`).**
   - **What happened:** the first verifier design ACCEPTED a deliberately bad candidate that dropped the constant `STATUS=OPEN` filter. All evidence states had every call OPEN, so the constant was never exercised: a false accept, the stop-condition-S2 risk.
   - **Fix:** stage 3b **state perturbation**. The candidate and the unabstracted reference must agree on perturbed copies of every start state (all events CLOSED; alternate events CLOSED), with both source and counterfactual values.
   - **Scope:** registered before any scenario existed or any discovery was evaluated. It is reported as a finding: an evidence-only verifier needs state diversity to detect constant-dropping.
2. **Before DEV (retrieval smoke on hand-written requests, not scenarios).**
   - **What happened:** the frozen LLM often names the single argument by its role word (`calls_with(who=Carol)`) or positionally (`calls_with(3)`), so the exact-name check refused it.
   - **Registered rule:** when a procedure has exactly ONE parameter and the LLM supplies exactly one argument, that argument binds to the parameter. The vocabulary-type and occurs-in-request checks still apply. Multi-parameter calls still require exact parameter names.
   - **Scope:** a deterministic compatibility rule. It gives the LLM no authority.
3. **DEV tuning after DEV v1** (LOCKED_TEST already generated and hash-frozen, never inspected).
   - **DEV v1 DISCOVERED result:** SCENARIO_EXACT .60, retrieval .52. The LLM ranking was right in most failures. The frozen LLM's *argument text* failed the deterministic checks: lowercased names, positional arguments, spurious arguments, a hallucinated few-shot procedure, no composition.
   - **Change (a), deterministic argument repair:** case-insensitive vocabulary canonicalization; type-directed binding of misnamed / positional arguments (value classes are disjoint); non-value leftovers are dropped and logged.
   - **Change (b), fallback:** typed candidate values from the request, plus a type-directed composition search (ACTIVE procedures whose return type fills a missing parameter, depth 1). The LLM ranks the candidates, with the same margin → CLARIFY rule.
   - **Change (c), metrics:** PROCEDURE_RETRIEVAL_BEHAVIORAL (an equivalent plan with identical status / return / state) is reported next to the strict metric; the gate stays on strict.
   - **Change (d), scenario fix:** P11 in DEV v1 used one-shot teaching for a family whose parameter occurs in two slots, which the registered one-shot rule correctly refuses. The DEV generator now uses two examples for P11, and DEV was regenerated as **DEV v2** (v1 results kept in `results/dev_v1/`).
   - **Consequence for LOCKED_TEST:** it was generated by the v1 generator and stays frozen, so its P11 scenario keeps the one-shot design. It is expected to fail by design, and that will be reported.
4. **DEV tuning after DEV v2** (LOCKED_TEST_v2 frozen, never inspected).
   - **What happened:** the only remaining misses were P12 requests served equally by the stored composite or by the dynamic composition `count_calls_with(person_on_call_at(t))`. Two were answered correctly by composition, which is a strict-metric miss; one near-tie (margin .08) became an unnecessary CLARIFY between behaviorally identical options.
   - **General runtime rule (stored-procedure reuse canonicalization, spec §57 / §61):**
     - a plan that is exactly the expansion of an ACTIVE composite procedure (a CALL-only body) is rewritten to call that stored procedure;
     - on a ranking near-tie, both top candidates are resolved and canonicalized, and when they are the same plan there is no ambiguity. Otherwise CLARIFY, as before.
   - **Scope:** it applies identically to every run.
   - **Tightened (the user / ChatGPT review) before DEV v3, and this is the form used everywhere:**
     - the score margin only selects candidates; equivalence is purely STRUCTURAL;
     - all candidates within the margin are resolved and canonicalized (expansion of ACTIVE stored composites) and collapsed into one semantic candidate before ambiguity is decided;
     - CLARIFY iff more than one DISTINCT canonical plan remains.
   - **New diagnostics:** BEHAVIORAL_PLAN_EXACT, STORED_PROCEDURE_REUSE_EXACT, DYNAMIC_RECOMPOSITION_RATE, EQUIVALENT_PLAN_COLLAPSE_COUNT, FALSE_AMBIGUITY_COUNT.
   - **Unchanged:** the strict PROCEDURE_RETRIEVAL_EXACT gate (.95).
   - **Run history:** a partial DEV run with the earlier top-2 form was stopped and archived (`results/dev_v3_ABORTED_partial_superseded_rule`); it is not used.
5. **Unit test `alias_and_ambiguous_retrieval` updated** to the change-#3 behaviour: the hallucinated value is rejected and the typed fallback binds the in-request value. A new case was added: a request with no valid typed value must CLARIFY. This found no functional regression. It was updated before the freeze.
